# 1. 项目概述

## 1.1 背景与目标

**项目背景**

结合需求梳理与旧版文化惠票务系统在用户体验、功能完善等方面的不足，产研团队作出新版文化惠平台的系统设计方案。广西地区演艺资源丰富，有传统戏曲、民族歌舞、非遗技艺展示等多种形式。但目前这些资源比较分散，用户想找到合适的演出或体验不太方便，资源提供方也缺少统一的展示渠道。

**建设目标**

本次系统建设旨在开发一套功能完善、安全可靠、智能化的文化惠票务系统。2026年整体升级目标：围绕"大数据分析、用户精准画像、AI智能服务、全区演艺场馆与剧目资源整合"四大方向，实现平台从基础服务向智能化、精细化、一体化升级，提升运营决策能力、用户服务能力和行业影响力，最终达成"一站式文化消费入口+产业服务枢纽"的建设目标。

我们希望做一个平台，把演出、场馆、艺人、非遗传承这些资源集中起来，让用户可以方便地浏览和预约，资源方可以发布信息和管理订单，运营人员可以看到数据分析。

**使用对象**
- 普通用户：找演出、预约、看订单
- 资源合作方：发布资源、接收订单
- 管理员：审核内容、处理订单、查看数据

**开发思路**

按老师建议的"先基础、后智能、再优化"来做：
1. 第一步做好基本的浏览、预约、审核、支付流程
2. 第二步加上推荐、AI客服这些辅助功能
3. 第三步完善统计分析和运营工具

## 1.2 范围与交付物

1. **H5手机端**：用户浏览资源、下单、查看订单
2. **电脑网页端**：桌面版浏览和预约

# 3. 项目阶段

## 3.1 基础阶段：业务流程打通

**这个阶段完成的功能**

基本把用户找资源、下单、付款、拿票这个流程做通了：
- 用户注册登录，分普通用户、资源方、管理员三种角色
- 做了10类资源：演出、场馆、艺人、非遗、文旅、文创、版权、设备、数字演出、配套服务
- 可以搜索、筛选、收藏资源
- 预约流程：提交→管理员审核→模拟支付→订单完成
- 库存管理：演出按天扣减库存，场馆按时段占用
- 售后：可以取消订单、申请退款
- 需求发布：用户发需求，管理员审核
- 评论功能：可以评分评论，需要审核通过
- 消息通知：订单状态变化会发消息

**怎么验证的**

实际跑了几遍流程：
- 手机端浏览资源，点进去看详情，提交预约
- 后台登录管理员账号，看到待审核订单，审核通过
- 用户端模拟支付（没有对接真实支付），订单变成已支付
- 试了重复预约同一时段的场馆，系统拒绝了
- 试了库存为0的演出，提示库存不足
- 操作都有日志记录

## 3.2 智能阶段：增加辅助功能

**这个阶段加的功能**

基础流程能走通之后，加了一些让用户体验更好的功能：

用户画像和推荐：
- 根据用户消费金额、次数、最近活跃时间打标签
- 把用户分成VIP用户、活跃用户、新用户、流失用户几类
- 手机端和电脑端各有一套推荐逻辑，结合用户兴趣、浏览记录、收藏记录来排序
- 用户发需求后，系统自动筛选匹配的资源

AI相关功能：
- 运营问数：管理员可以问"最近一周交易额多少"这种问题，接入了DeepSeek的API
- 智能客服：用户问订单相关问题，AI回答
- 文案生成：帮运营生成宣传文案

**关于AI的说明**

因为课程经费有限，我们用的是DeepSeek这个比较便宜的API。如果API调用失败（比如网络问题、余额不足），会自动切换到本地写的规则来兜底，不会让功能完全不可用。另外做了限流，防止费用超了。

没有做模型训练和数字孪生这种更复杂的东西。

**测试情况**

- 改了兴趣偏好之后，推荐列表的顺序确实变了
- 分群功能看了下数据，分类是对的
- AI客服能回答基本的订单问题
- 试了关掉API，功能还能用（用的规则兜底）

# 9. 技术风险与成本告知

## 9.1 技术与业务风险

| 风险 | 影响 | 当前措施 | 残留风险/后续计划 |
|------|------|---------|-----------------|
| **AI模型幻觉** | 回答不准确 | 回退本地规则 | 需要持续监控和优化提示词 |
| **AI费用超支** | 成本失控 | 限额+限流 | 需要预算告警 |
| **模拟数据局限** | 无法验证真实效果 | 明确标注模拟 | 需要真实数据验证 |
| **HTTP安全性** | 数据明文传输 | 演示环境可接受 | 生产需HTTPS |
| **单机性能瓶颈** | 高并发限制 | 当前访问量低 | 需要负载均衡+缓存 |
| **串行写入限制** | 写入QPS受限 | 事务保证一致性 | 需要读写分离 |
| **外部接口依赖** | DeepSeek不可用 | 自动回退规则 | 需要多接口冗余 |
| **移动端兼容性** | 部分设备未测试 | 主流浏览器通过 | 需要真机测试 |
