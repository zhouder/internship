# 补充功能与验收（2026-11-11）

本次按“最低可用、可复测”补充老师新增范围。H5、电脑网页、后台仍为三个入口；微信、北部湾银行、大麦等复用甲方现有渠道，当前不自行接入真实支付。

| 功能 | 入口和最小实现 | 保留边界 |
|---|---|---|
| 模拟余额 | 用户“我的→模拟钱包与优惠券”增加余额，订单确认后可余额支付；审核退款返还同额，记账本 | 没有真实充值、银行扣款、提现或支付回调 |
| 演示优惠券 | 后台“票务与运营”建券，用户领券，预约时选券，服务端核对门槛/期限；提交占用，支付使用，取消/退款返还 | 每人每券一种模板限领一次，每单一张；不支持叠加、部分退款或外部发券 |
| 分场次余量与选座 | 演出固定14:00/19:30两种模拟场次，独立配额；前60席可点击选座，不选时自动配票 | 示例座位图，非真实场馆座位或甲方实时票池；旧全天订单保守占用各场次 |
| 分时租赁 | 场馆/设备选择起止时间，重叠时拒绝，相邻时段可分别预约 | 按展示单价收费，不自动折算小时价；未将整场租赁与关联剧目排期互锁 |
| 电子票与自助出票 | 演出订单支付后自动生成随机唯一票码、二维码；“电子票/打印”查看；旧已支付有效演出单可手动补发 | 每张票仅对应单个演出名额，不对接真实渠道出票机 |
| 打印管理（老师29项） | 单张/批量浏览器打印或保存PDF，记录请求时间、用户及票码 | 记录打印请求，不能确认打印机真实出纸；真实设备驱动另验 |
| 核销管理（30项） | 管理后台输入票码，服务端校验订单、日期、票状态，仅核销一次；全部使用后订单完成 | 演示允许提前核销未来场次；已有用票不支持整单退款，无生产防伪体系 |
| PDA流程（31项） | 后台手机适配核销页；键盘或键盘式扫码枪输入，设备支持时振动；离线开关暂存票码，联网批量校验 | 未接真实PDA SDK、摄像头扫描；离线暂存不是离线核销成功；浏览器清理数据会丢待校验队列 |
| 微信/银行/大麦（32—34项） | 保留已有模拟支付、渠道订单及库存同步流程和日志 | 按老师要求复用甲方渠道；正式对接依赖甲方接口、权限和测试环境 |
| 自助出票（35项） | 用户从本人演出订单查看电子票并打印，票与订单关联 | 无实体自助机或专用打印机验收 |
| 每日画像快照 | ECS定时任务北京时间00:10左右执行；手动按钮仍保留；每用户每天upsert一份 | 不是画像模型训练；不回填不存在的历史快照；Vercel环境未配置此ECS任务 |
| 渠道推荐策略 | 后台分别设置H5/电脑网页的兴趣、浏览、收藏、购买、同城权重；用户页面下次刷新生效 | 可解释规则打分，无A/B分流、自动学习 |
| 模拟营销复盘 | 后台建活动和归属券，领券下单归因；看订单/有效付费、净交易额、模拟转化率、ROAS并下载报告 | 曝光、点击、预算为人工示例输入；ROAS不等于净利润ROI，无真实广告归因 |

## 小组复测顺序

1. 用户登录→“我的”领券并增加模拟余额→打开演出详情，选择预约、日期、场次和座位→选券提交。
2. 管理员在交易管理确认→用户用模拟余额支付→查看折后金额、电子票与二维码→单张/批量打印或保存PDF。
3. 管理员在“票务与运营”输入票码：第一次成功，重复失败；全部票用完后订单完成。用第二笔订单验证退款：退款审核中不能核销，退款成功作废票并返还模拟余额和券。
4. 打开模拟离线，输入票码只应显示“待校验”；关闭离线后联网校验，重复/已作废票应被拒绝。
5. 同一场次同座位并发只允许一笔；不同场次可选同座位；场馆09:00—12:00和12:00—14:00可分别预约，重叠时段失败。
6. 后台建活动和归属优惠券，用户领券下单支付，复盘净额增加；成功退款后剔除。测试零预算、零点击应显示“—”。
7. 手动保存快照，检查后台最近保存时间；服务器定时器、备份与日志按部署说明检查。

## 运行与技术说明

- 新增业务表：demo_wallets、demo_wallet_entries、demo_campaigns、demo_coupons、demo_coupon_claims、demo_tickets、demo_print_requests。金额统一使用整数分。字段以server/extension-schema.mjs为准。
- 订单新增：gross_amount、discount_amount、coupon_claim、campaign_code、payment_method、session_time、seat_labels、start_time、end_time；原字段与旧库存模式保留。
- 所有写请求沿用SQLite事务或PostgreSQL事务锁；余额支付、订单、券、出票作为同一请求提交/回滚。打印请求只写日志。
- 新API前缀为/api/demo；本人权益/api/benefits，订单票据/api/orders/:id/tickets。普通账号不能操作营销配置或核销，也不能读取/打印他人的票据。
- 画像任务：node scripts/snapshot-profiles.mjs；ECS使用guiyan-snapshot.service/timer，数据库凭据只从受保护环境文件读取。
- 本机并发基线：node --experimental-sqlite scripts/benchmark.mjs，使用独立内存数据库，不触碰线上数据，不调用AI。单批20并发争抢5席，预期5成功、15库存不足；这不是生产容量或稳定吞吐量承诺。
- 真实PDA/打印机、真实支付/售票渠道、Safari与真实手机专项、四环境灰度、Redis/高可用/灾备仍是后续工作，不写成已经完成。
